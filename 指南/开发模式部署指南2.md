> 适用项目：`/root/home/workspace_cribc/fqx_weknora/qj-weknora`（以下简称 **qj-weknora**）
> 用途：qj-weknora 是从旧 pg-fqx 调试版拷贝而来的**独立二开环境**，目标是隔离旧共享基建，并适配 OceanBase 4.2 + Elasticsearch 8.18。

## 2. 首次部署（从零开始）

### 2.1 启动独立基础设施（只做一次）

```bash
cd /root/home/workspace_cribc/fqx_weknora/qj-weknora

# 启动 qj 独立 PG(65433) + Redis(16380)
docker compose -f docker-compose.qj.yml -p weknora-qj up -d
```

> ⚠️ **不要**用 `make dev-start` / `make dev-bg`——那会启动共享 `weknora-dev` 的基建（65432/16379），不是 qj 这套。

### 2.2 启动后端

```bash
cd /root/home/workspace_cribc/fqx_weknora/qj-weknora
make dev-app        # 前台，air 热重载
# 或后台：
make dev-app-bg     # 日志写 log.log
```

首次启动时，空库会自动跑迁移建表（约 105 个 versioned migration），等待 `Server is running at 0.0.0.0:8085` 出现。

### 2.3 启动前端

```bash
cd /root/home/workspace_cribc/fqx_weknora/qj-weknora
make dev-frontend        # 前台
# 或后台：
make dev-frontend-bg
```

### 2.4 访问地址

- 前端：`http://<server-ip>:5175`
- 后端 API：`http://<server-ip>:8085`
- Swagger：`http://<server-ip>:8085/swagger/index.html`

## 3. 日常运维命令

### 3.1 启停

| 操作 | 命令 |
|---|---|
| 启动独立基建 | `docker compose -f docker-compose.qj.yml -p weknora-qj up -d` |
| 停止独立基建 | `docker compose -f docker-compose.qj.yml -p weknora-qj down` |
| 重启独立基建 | `docker compose -f docker-compose.qj.yml -p weknora-qj restart` |
| 启动后端（前台） | `make dev-app` |
| 启动后端（后台） | `make dev-app-bg` |
| 停止后端 | `make dev-app-bg-stop` 或 `Ctrl+C` |
| 重启后端 | `make dev-app-bg-restart` |
| 启动前端（后台） | `make dev-frontend-bg` |
| 停止前端 | `make dev-frontend-bg-stop` |
| 重启前端 | `make dev-frontend-bg-restart` |

### 3.2 状态检查

```bash
# 后端进程
ss -tlnp | grep 8085

# 前端进程
ss -tlnp | grep 5175

# 独立 PG / Redis
docker compose -f docker-compose.qj.yml -p weknora-qj ps

# 验证 qj 数据在自己的库里（不是共享库）
psql -h 127.0.0.1 -p 65433 -U postgres -d WeKnora -c "\dt" | head
```

### 3.3 日志

## 4. 配置说明（`.env.local`）

`.env.local` 不提交 git，是 qj 独立环境的关键覆盖配置。模板：

```bash
# ===== 独立基础设施（与共享 dev 隔离）=====
DB_HOST=127.0.0.1
DB_PORT=65433
REDIS_ADDR=127.0.0.1:16380
REDIS_DB=0

# ===== DocReader 复用共享 =====
DOCREADER_ADDR=127.0.0.1:15051

# ===== 独立文件存储（不指向 my_weknora）=====
# 留空即使用项目自己的 .local-data/files

# ===== 图谱暂关（阶段 3 后再评估）=====
NEO4J_ENABLE=false

# ===== 阶段 2 起：ES 检索 =====
# RETRIEVE_DRIVER=elasticsearch_v8
# ELASTICSEARCH_ADDR=http://127.0.0.1:9200
# ELASTICSEARCH_USERNAME=elastic
# ELASTICSEARCH_PASSWORD=<set>
# ELASTICSEARCH_INDEX=WeKnora

# ===== 阶段 3 起：切 OceanBase =====
# DB_DRIVER=mysql
# DB_HOST=127.0.0.1
# DB_PORT=2881
# DB_NAME=WeKnora
# DB_USER=<ob_user>
# DB_PASSWORD=<set>
```

## 5. 隔离验证清单（每次启动后确认）

启动 qj 后，跑以下三条确认没连错库：

```bash
# 1. 后端环境变量显示连的是 65433
cat /proc/$(cat pid.app)/environ 2>/dev/null | tr '\0' '\n' | grep -E "DB_PORT|REDIS_ADDR"

# 2. 共享库 65432 里看不到 qj 新建的数据
psql -h 127.0.0.1 -p 65432 -U postgres -d WeKnora -c "SELECT count(*) FROM knowledge_bases;"

# 3. 自己的库 65433 有数据
psql -h 127.0.0.1 -p 65433 -U postgres -d WeKnora -c "SELECT count(*) FROM knowledge_bases;"
```

> 如果第 1 条显示 `DB_PORT=65432`，说明启动脚本硬编码没改干净，回到适配方案 01 的阶段 1.4 检查。

## 6. 常见问题

### Q1：qj 后端报 Redis 连接失败？
独立 Redis（16380）没启动。先 `docker compose -f docker-compose.qj.yml -p weknora-qj up -d redis`。

### Q2：上传文档报 `DOCREADER_PARSE_FAILED: failed to get file`？
DocReader 是共享的（15051），但文件存在 qj 自己的磁盘上。因为 qj 用独立 Redis，任务不会被旧 pg-fqx 的 worker 抢走，正常不应出现此错。如果出现，检查 `.env.local` 是否误删了 `LOCAL_STORAGE_BASE_DIR` 指向独立目录。

### Q3：想临时用共享库调试？
**不推荐**。如果一定要，在 `.env.local` 里把 `DB_PORT=65432`、`REDIS_ADDR=127.0.0.1:16379` 改了，**用完立刻改回**。

### Q4：端口被占（8085/5175）？
```bash
ss -tlnp | grep 8085
fuser -k 8085/tcp     # 杀占用进程
```

### Q5：阶段 2 切 ES 后，老的 PG 向量数据怎么办？
用 cli 的 `reindex` 子命令从 PG embeddings 表回填 ES（开发中，见适配方案 01 阶段 4）。

## 7. 与旧 pg-fqx 的共存关系

- qj（8085/5175）和旧 pg-fqx（8083/5174）**可以同时运行**，互不影响
- 两者连的是不同的库（qj→65433，旧→65432）、不同的 Redis（qj→16380，旧→16379）
- 唯一共享的是 DocReader（15051），无状态，安全
- **不要**在 qj 里跑 `make dev-start`——那会启动共享基建，可能影响旧 pg-fqx
